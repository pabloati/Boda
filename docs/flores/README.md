# Botanical plates on the site: handoff notes

State at 2026-11-09, branch `flores` (not merged into `main`). Written so a new session can continue without the chat.

## What this is

Pablo wants 19th-century botanical engravings (public domain) as **colour** decoration on the section backgrounds, and to mix different flowers by placing them himself, like in Canva or PowerPoint. What exists:

- `_dev/flores.html` — the local editor. Loads the real `index.html` in a phone or desktop frame, library of flowers on the left, panel on the right, smart guides, undo, Ctrl+S. Run `python3 _dev/serve.py [port]` and open `/_dev/flores.html`. The save is a POST that only `_dev/serve.py` handles (`/_dev/save-flores`, validated, writes `js/flores-layout.js`).
- `js/flores.js` — draws the layout on the page. `js/flores-layout.js` — the layout, **generated by the editor, never edited by hand**. It is empty (`{"items": []}`) so the live site is unchanged until Pablo places flowers.
- `assets/flores/*.png` + `flores.json` — 11 colour cut-outs, 640 px high, quantised (836 KB total). `flores.json` lists them for the editor and says which sides of each plate were cut when it was cropped (`cut`).
- CSS block "Botanical plates" at the end of `css/styles.css`: `.has-flores` (clip + own stacking context), `.flor` (`z-index: -1`, behind the text), `.flor--front`, `.flor--no-m` / `--no-d`.

Model of one item: `{id, sec, img, w, x:{a:'l'|'r', v}, y:{a:'t'|'b', v}, flip, rot, front, hide:''|'m'|'d'}`. Offsets are px from the **nearest edge** of the section, so a flower flush with an edge stays flush when the section resizes. `sec` is a section id (`intro countdown locations timeline rsvp gifts playlist social`) or `footer`. The hero is not editable (sticky veil).

## Design decisions (all agreed with Pablo)

- **Page tones stay the site's neutrals** (paper, olive, ink). Nothing is tinted with a flower colour: Pablo said the tinted veil "queda raro". A palette only adds **one accent** (button, times) taken from the flower and darkened to >= 4.5:1 with white text. Five proposals are in `docs/flores/flores-a-color.pdf` (local, not committed; regenerate with `tools/gen_color.py` + `tools/render.mjs`).
- **Free placement with PowerPoint-style snapping**, not enforced rules. The panel only warns when a cut side of a plate is visible and not flush with an edge. Earlier idea, still useful as a guideline: no flower floating mid-section, a cut edge goes flush with a section change or the screen edge.
- Editor is **local only** (`_dev/` is not published by GitHub Pages).
- Cherry (Köhler) was left out: fruit and dissections like the almond plate, the main branch did not isolate cleanly. Needs a hand crop.

## How the cut-outs were made (reproducible)

1. Plates are public-domain scans (pre-1900). Sources actually used: Cleveland Museum of Art open access (CC0, via Internet Archive): `narciso-jonquilla` (Bessa, Flore des jardiniers) and `jacinto` (Curtis's Botanical Magazine 1806). From Wikimedia Commons (hosting of the original books): Jan Kops, Flora Batava (poeticus, muscari, crocus, both anemones), Redouté Les Liliacées (trompón), Köhler's Medizinal-Pflanzen 1890 (muguete, manzano), H. Witte Flora 1868 (glicinia). `tools/download_plates.py <empty folder>` downloads them. **Not usable**: Europeana herbarium sheets (CC BY-SA), Met / Art Institute of Chicago / Rijksmuseum APIs (blocked or gone), Smithsonian DEMO_KEY (rate-limited).
2. `tools/cutout.py <raw folder> <out folder> tools/spec_color.json` crops each plate (`crop` and `mask` are fractions of the original), removes the paper by colour distance and writes a transparent PNG with no edge fade. `tools/lineart.py` is the older olive line-art version (not used by the editor).
3. `tools/cuts.json` = which sides of each cut-out touch the crop edge (computed from the alpha border; threshold 0.15).
4. `python3 _dev/flores_export.py` resizes and quantises into `assets/flores/` and writes `flores.json` (needs `docs/flores/img/color/*.png` from step 2 and `cuts.json`).

`tools/test_editor.mjs` is the Playwright check I used (add a flower, drag to an edge, save, load the real page). Its paths point at a scratch folder and the Playwright install under `~/.npm/_npx`: adapt before running. Always run it on a spare port and restore `js/flores-layout.js` afterwards.

## Gotchas

- Do not run `pkill -f "serve.py 8099"` inside a Bash tool call: the pattern is in the command line and kills the shell. Free the port by PID.
- Flowers are behind the text, so the browser hands clicks to the text: the editor finds a flower by position (`hit()`), not by element.
- Pablo's browser could not reach `localhost:8000` once; changing the port fixed it.
